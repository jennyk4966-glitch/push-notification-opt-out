광고성 앱푸시 수신거부 처리 로직

광고성 앱푸시 내 [수신거부] 버튼 클릭부터 TMS 및 회원정보 반영, 완료 안내까지의 전체 정책 및 화면 흐름.

메시지광고성 앱푸시
대상 사용자회원 / 비회원
연동 기준기존 앱 설치 시 동의 로직

1. 개요

목적

광고성 앱푸시 내 [수신거부] 버튼을 제공하여 로그인 여부와 관계없이 사용자가 광고성 앱푸시 수신을 철회할 수 있도록 한다.

수신거부 처리 시 기기 및 회원의 광고성 앱푸시 수신동의 상태를 연동하며, 기존 앱 설치 시 광고성 앱푸시 동의 처리 로직과 동일한 기준을 적용한다.

적용 대상

  • 하나투어 APP
  • 광고성 앱푸시
  • 회원 / 비회원
  • 로그인 / 비로그인 상태 모두 포함

2. 기본 정책

구분정책
수신거부 진입광고성 앱푸시 내 [수신거부] 버튼 제공
사용자 의사 확인버튼 클릭 즉시 거부 처리하지 않고 확인 팝업 1회 노출
수신거부 확정확인 팝업에서 [수신거부] 선택 시 TMS로 수신거부 정보 전달
비로그인기기(Device) 기준 광고성 앱푸시 수신동의 N 처리
로그인기기 + 회원 기준 광고성 앱푸시 수신동의 N 처리
비로그인 → 로그인기존 기기의 N 상태를 로그인 시 회원정보에도 N으로 연동
정보성 알림광고성 앱푸시만 수신거부하며 예약/결제 등 정보성 PUSH 수신에는 영향 없음
연동 기준기존 앱 설치 시 앱푸시 동의 및 로그인 연동 로직과 동일한 방식 적용
※ TMS는 기기별 동의값을 기준으로 푸시 타깃을 제어하며, 기기 동의가 N인 경우 회원 광고성 동의가 Y이더라도 해당 기기는 발송 대상에서 제외되는 구조로 확인됨.

3. 전체 처리 Flow

광고성 앱푸시 수신
→
[수신거부] 클릭
→
앱 실행/활성화
→
거부 확인 팝업
→
TMS 요청
→
로그인 여부 확인
→
기기/회원정보 반영
→
완료 팝업

취소 시

  • TMS 전송하지 않음
  • 기기 동의값 변경하지 않음
  • 회원 동의값 변경하지 않음
  • 기존 화면 유지

4. 로그인 상태별 처리 로직

4-1. 비로그인 상태

처리 Flow

광고성 앱푸시 [수신거부] → 확인 팝업 → 수신거부 확정 → TMS 전달 → Device 기준 광고성 앱푸시 동의 N 처리 → 완료 팝업

항목결과
기기 광고성 앱푸시 동의N
회원 광고성 앱푸시 동의미반영

비로그인 상태이므로 회원정보에는 즉시 반영하지 않고 기기정보 기준으로 수신거부 상태를 저장한다.

4-2. 로그인 상태

처리 Flow

광고성 앱푸시 [수신거부] → 확인 팝업 → 수신거부 확정 → TMS 전달 → Device N → 회원 앱푸시 동의 N 연동 → 완료 팝업

항목결과
기기 광고성 앱푸시 동의N
회원 광고성 앱푸시 동의N

마이페이지 앱푸시 설정에서도 변경된 N 상태가 확인되어야 한다.

4-3. 비로그인 상태에서 수신거부 후 로그인

비로그인 상태에서 수신거부 → Device 광고성 앱푸시 동의 N → 이후 동일 기기에서 로그인 → 기기정보와 회원정보 매핑 → 기존 Device N 상태를 회원정보에도 N으로 반영

별도 신규 정책을 생성하지 않고 기존 앱 설치 후 로그인 시 기기의 앱푸시 동의상태를 회원정보에 연동하는 기존 로직과 동일하게 적용한다.

5. 앱 실행 상태별 처리

5-1. 기본 원칙

앱이 이미 실행 중인 경우 사용자가 상품 탐색, 예약, 결제 등을 진행 중일 수 있으므로 광고성 앱푸시 수신거부를 위해 홈으로 강제 이동하지 않는다.

현재 이용 중인 화면을 유지하고 해당 화면 위에 공통 수신거부 확인 팝업을 노출한다.

현재 앱 화면처리 방식
홈현재 화면 유지 + 수신거부 팝업
상품/콘텐츠현재 화면 유지 + 수신거부 팝업
예약 진행예약 진행 상태 유지 + 수신거부 팝업
결제 진행결제 진행 상태 유지 + 수신거부 팝업
마이페이지 일반 화면현재 화면 유지 + 수신거부 팝업
설정 > 광고성 정보 수신 동의 화면로그인 상태에서만 접근 가능
현재 화면 유지 + 수신거부 팝업 → 처리 후 앱푸시 설정값 Refresh

5-2. 예약/결제 진행 중

현재 페이지 유지 → 수신거부 팝업 노출 → 처리 완료 → 기존 페이지 그대로 유지

  • 예약 진행 단계
  • 사용자가 입력한 예약정보
  • 상품 선택 상태
  • 결제 진행 상태

5-3. 설정 > 광고성 정보 수신 동의 화면에서 처리 (로그인 상태만)

해당 화면은 로그인 상태에서만 접근 가능하다. 비로그인 상태에서는 앱푸시 설정 화면으로 진입할 수 없다.

설정 화면 → 수신거부 팝업 → N 처리 → 설정 API 재조회 또는 화면 Refresh → 광고성 앱푸시 수신거부/OFF 상태 노출

7. TMS / 회원정보 연동

처리 시점TMS Device회원정보비고
비로그인 수신거부N-Device 기준 저장
로그인 수신거부NN기기 + 회원 동시 연동
비로그인 N 후 로그인N 유지N로그인 시 회원정보 연동

처리 원칙

  • TMS에는 광고성 메시지 수신거부 정보를 전달
  • 회원 로그인 상태라면 회원의 광고성 앱푸시 동의정보까지 반영
  • 비로그인 상태에서는 Device에만 저장
  • 이후 로그인 시 Device에 저장된 상태를 회원에 연동
  • 기존 앱 설치 시 동의 로직과 동일한 구조를 사용

9. 최종 정책 요약

광고성 앱푸시 [수신거부] 클릭 → 현재 이용 화면 유지 → 거부 확인 팝업 → 사용자가 수신거부 확정 → TMS 전달 → 비로그인 시 Device N → 로그인 시 Device N + 회원 N → 비로그인 N 이후 로그인 시 회원정보 N 연동 → 처리 완료 팝업

앱 실행 중에도 홈으로 이동하지 않고 현재 화면 위에 팝업을 노출하며, 로그인 상태에서 설정의 광고성 정보 수신 동의 화면에서 처리된 경우 앱푸시 항목을 최신 동의정보로 Refresh한다. 비로그인 상태에서는 해당 설정 화면에 접근할 수 없다.
기기 알림 권한 및 예약/결제 등 정보성 알림에는 영향을 주지 않고 광고성 정보 수신여부(앱푸시)만 수신거부 처리한다.
