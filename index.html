1. 개요

목적

  • 광고성 앱푸시 내 수신거부 기능 제공
  • 로그인 절차 없이 수신거부 처리
  • 수신거부 결과를 TMS와 Braze에 동일 시점 반영

적용 원칙

  • 앱푸시 Y/N 변경 기존 공통 처리 로직 활용
  • 화면별 Braze 태깅 개별 추가 없음
  • 기존 TMS 전송 시점에 Braze 값 동시 전송
  • Y→N, N→Y 모두 동일 구조 적용
  • OS 전체 알림 권한 및 정보성 푸시 수신 여부 변경 없음
Braze 태깅 상세 정의 · Attribute/Event 명 · 데이터 타입 · 값 규칙 · 식별키 · 테스트 조건 → 별도 태깅정의서 전달 예정

2. AS-IS

TMS

  • Device ID 기준 앱푸시 수신동의 관리
  • 앱푸시 Y/N 변경 시 SDK/API로 즉시 전달
  • Device N → TMS 광고성 앱푸시 발송 제외

Braze

  • TMS 미경유 발송
  • Braze SDK · 프로필 · 기기정보 기반 발송
  • 회원 동의값 → Neon → Cobalt → Braze 경로 반영
  • 회원 동의값 약 10분 주기 반영

3. TO-BE

개선 구조

  • 앱푸시 Y/N 변경 공통 처리 지점 기준
  • TMS 전송과 동시에 Braze 값 전송
  • 신규 수신거부 버튼 포함 기존 앱푸시 Y/N 변경 영역 동일 적용
  • 화면별 Braze 전송 로직 중복 구현 없음

4. 상태별 처리

4-1. 비로그인 / 로그아웃

  • 광고성 푸시알림 수신거부 선택
  • 확인 팝업 → 수신거부 확정
  • 앱푸시 N 변경
  • TMS N + Braze N 동시 전송
  • 로그인 요구 없음
  • 회원정보 즉시 변경 대상 아님

4-2. 로그인

  • 광고성 푸시알림 수신거부 선택
  • 확인 팝업 → 수신거부 확정
  • 앱푸시 N 변경
  • TMS N + Braze N 동시 전송
  • 기존 회원 동의정보 연동 로직 유지

4-3. 재동의

  • 기존 앱 설정 등에서 앱푸시 N→Y 변경
  • 동일 공통 처리 지점 사용
  • TMS Y + Braze Y 동시 전송
